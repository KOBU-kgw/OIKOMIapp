# v1.3 デバッグ計画

## 概要
v1.3の4柱（TGL計算改訂、ソート安定化、削除寛容化、操作パターン刷新）は全て実装済み。静的解析と既知の問題を修正する。

## 発見された問題

### Bug 1: 通知スロット6件目がキャンセルされない（中）
- **ファイル**: `lib/services/notification_service.dart`
- **問題**: hopeless通知がスロット4に格納され、状態遷移通知がスロット0-3に入る。合計6件だが`cancelNotificationsForTask`は5件（0-4）しかキャンセルしない。スロット5が孤立する。
- **修正**: hopeless通知のスロットを5に変更し、状態遷移通知を0-3に変更。キャンセルループも6件に拡張。

### Bug 2: バージョン番号未更新（小）
- **ファイル**: `lib/screens/settings_screen.dart:129`
- **問題**: `1.1.0`のまま。v1.3に更新が必要。
- **修正**: `'1.3.0'`に変更。

### Bug 3: テストファイルがダミー（小）
- **ファイル**: `test/widget_test.dart`
- **問題**: デフォルトのカウンターテスト。OIKOMIアプリを全くテストしていない。実行すると失敗する。
- **修正**: テストを削除し、将来的に書くか、至少しない。

### 潜在的問題: purgeStaleDeleted()の仕様乖離
- **ファイル**: `lib/services/database_service.dart:87-95`
- **問題**: 計画では「5秒以上前のものを物理削除」とあるが、実装では起動時に全てのsoft-deletedタスクを物理削除する。
- **判定**: 実用上問題なし（アプリ再起動時にUndo猶予は既に無効）。計画ドキュメントの方が古い。修正不要。

## 実装手順

### Step 1: 通知スロット修正
`lib/services/notification_service.dart` を修正:
1. `cancelNotificationsForTask` のループを `i < 5` → `i < 6` に変更
2. hopeless通知のIDを `_notificationId(task.id, 4)` → `_notificationId(task.id, 5)` に変更
3. `_notificationMessage` の hopeless ケースで `TGLState.war` ではなく `TGLState.overdue` を返すよう変更（hopelessは期限超過に近い）

### Step 2: バージョン番号更新
`lib/screens/settings_screen.dart:129` の `'1.1.0'` → `'1.3.0'`

### Step 3: テストファイル削除
`test/widget_test.dart` を削除

### Step 4: 静的解析
`dart analyze` を実行してエラーがないことを確認

### Step 5: ビルド確認
`flutter build ios --no-codesign` または `flutter build apk --debug` でビルドが通ることを確認

## 検証方法
1. `dart analyze` — エラー0を確認
2. `flutter test` — テスト削除後は0件（OK）
3. ビルド確認 — コンパイルエラーがないことを確認
4. 手動動作確認（可能なら）:
   - タスク追加 → 通知スケジュール確認
   - タスク完了 → Undo SnackBar → 元に戻す → 通知復活
   - タスク削除 → Undo SnackBar → 元に戻す
   - タスカラップ → 詳細画面遷移 → 編集 → 保存
   - 左スワイプ → 完了ボタン → 完了
